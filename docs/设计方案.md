## P1:配置中心(其他一切自定义的地基)

新增 `Services/ConfigService.cs` + exe 旁 `config.json`,首启生成默认配置,`FileSystemWatcher` 监听变更热重载(改文件即生效,无需重启)。

> 现状:`ConfigService.cs` 骨架已落地(设置窗口读写天气/缩放/Coding Plan 等),但尚无热重载,`layout`/`sensors`/`appearance` 节点待扩展。

```jsonc
{
  "layout": { "orientation": "auto", "modules": ["clock","cpu","gpu","memory","network","disk","weather","todo"] },
  "sensors": {
    "fans": "auto",            // "auto"=全部有数据的 | ["CPU Fan","Fan #2"] 指定
    "disks": "auto",           // "auto"=最多3块 | ["C:","D:"] 指定
    "network": "auto"          // "auto"=活动网卡 | ["以太网","WLAN"] 指定多块
  },
  "appearance": {
    "theme": "cyber",          // cyber | eva | rog | light | custom
    "scale": 1.0,              // 全局缩放 0.8~1.3,适配不同视距
    "fontFamily": "Consolas",
    "background": {            // 需求 9
      "type": "theme",         // theme=主题底色(默认) | color | gradient | image
      "color": "#0A0E1A",
      "gradient": ["#0A0E1A", "#1E1030"],
      "image": { "path": "bg.jpg", "dim": 0.35 }   // 相对 exe 或绝对路径;dim 压暗保前景可读
    },
    "overrides": { "cpu.bigNumber": { "size": 44, "weight": "bold", "color": "#22D3EE" } }
  },
  "customText": { "lines": ["左手代码 右手年华"], "align": "center" },   // 需求 9:空数组=隐藏
  "weather": { "refreshMinutes": 30 },
  "todo": { "maxItems": 6 }
}
```

实现要点:XAML 样式全部改为 `DynamicResource`,配置变更时重写 Application.Resources,一处分发全局生效。

## P1:多风扇 / 多硬盘 / 多网卡

**风扇**:LHM 已枚举主板全部风扇(CPU Fan / 机箱 Fan#1~4 / 水泵)+ GPU 风扇。改造:
- 传感器选择从"单选"改为"列表"——`PickSensors` 返回全部匹配项
- UI:CPU/GPU 卡内风扇行扩展为风扇组(名称 + RPM + 迷你条,最多 4 行,超出合并显示)
- config `sensors.fans` 控制显示哪些

**硬盘**(新增 DISK 卡片):
- LHM 开 `IsStorageEnabled`:温度 + 占用率 + 读写速率(Smart + StoragePerformanceChecker)
- 免管理员降级:WMI `Win32_PerfFormattedData_PerfDisk_PhysicalDisk`(本地化安全)读读写速率和活动时间,温度需管理员
- UI:每盘两行(盘符+型号 / 温度·占用·↑↓速率),默认显示前 3 块

**网卡**:
- 现有"粘性选卡"扩展为多卡列表:DOWN/UP 主行显示主网卡,副网卡折叠为一行小字
- config `sensors.network` 指定显示哪几块

## P2:外观自定义(字体/大小/粗细/颜色,合并需求 5+6+9)

- `appearance.theme` 内置 4 套预设(cyber 青紫 / eva 绿 / rog 红紫 / light 浅色)+ custom
- `appearance.scale` 全局字号缩放;`overrides` 支持按元素路径覆写(元素路径清单写入 README):`cpu.bigNumber`、`network.downValue`、`custom.text`、`card.borderRadius`、`graph.lineThickness`、`bar.height` 等
- 配色:任意 hex,含背景/卡片/强调/告警五组色
- 全部走 DynamicResource 热重载,改完保存文件 1 秒内生效

## P2:背景与自定义文字信息(需求 9,与外观同体系实现)

**背景**(`appearance.background`):
- 四种模式:`theme`(主题底色,默认)/ `color`(纯色)/ `gradient`(双色垂直渐变)/ `image`(图片)
- image:按显示器分辨率 cover 填充(竖屏 440 宽裁剪居中);`dim` 压暗系数 0~1 在图片上叠一层黑色半透明遮罩,保证监控数字可读;路径相对 exe 或绝对,文件缺失时回退 theme 并提示
- 卡片背景可选半透明(`overrides` 的 `card.opacity`),让背景图透出来

**自定义文字**(`customText` + `layout.modules` 中的 `customText` 模块):
- 用途:座右铭、备注、手写信息条等自由文本
- `lines` 多行文本 + `align` 对齐;字号/颜色/字体走 `overrides.custom.text`,与需求 5 同一套
- 位置随 `layout.modules` 数组顺序调整(与需求 3 阶段 1 打通),默认置于时钟下方

## P2:UI 元素位置自定义(两阶段)

- **阶段 1(低成本)**:`layout.modules` 数组控制模块显隐与顺序,配合 `--config` 打开一个主屏上的设置窗口(WPF 窗口:模块列表 + 上下移 + 复选 + 主题/缩放选择),写回 config.json
- **阶段 2(自由拖放)**:面板上加"编辑模式"热键(如 E):解锁后所有卡片可拖动/改大小,网格吸附,底部出现"保存布局"按钮,坐标写入 config 的 `layout.freeform`。技术上是 Canvas 绝对布局替代 StackPanel,工作量约 1~2 天,放在阶段 1 验证需求后再做

## P2:横竖屏切换

> ✅ 已实现(2026-09-29):`config.json` 的 `orientation: auto | portrait | landscape` + 命令行 `--landscape` / `--portrait` + 设置窗口「屏幕方向」三处入口;auto 按目标副屏宽高比自动选。实现方式:XAML 内声明竖版/横版两套骨架,时钟、卡片等模块以 x:Name 共享,切换时由 `MoveTo` 运行时重新挂载(卡片实例唯一,数据绑定不重复);横版曲线图放 `*` 行自动填满卡片剩余高度,天气/额度卡片隐藏时另一半纵跨两行。

- `layout.orientation: auto | portrait | landscape`
- auto:按目标显示器宽高比自动选(高>宽→竖版单列;宽>高→横版双列网格,CPU/GPU 左右分栏,时钟居中)
- 布局引擎化:模块列表 + 布局描述(竖版 Grid.RowDefinitions 单列 / 横版 2×4 网格)生成容器
- 竖版 440×1920 与横版 1920×440 共用同一套模块组件

## 实施路线(2026-08-26 重排)

1. **P1 配置中心扩展**——现有 `ConfigService` 骨架上加 `FileSystemWatcher` 热重载 + `layout`/`sensors`/`appearance` 节点,XAML 改 DynamicResource。仍是一切自定义的地基,但骨架已在,工作量小于原估
2. **P2 外观自定义(5+6)+ 背景与自定义文字(9)**——三者同属 `appearance`/overrides/DynamicResource 一套体系,一次做完避免反复动样式层;需求 9 为新提,优先兑现
3. **P1 多传感器(2)**——风扇列表化、DISK 卡片、多网卡;数据层独立改造,不依赖也不阻塞外观,故排后
4. **P2 横竖屏(7)**——依赖路线 1 的模块化布局引擎;放外观定型之后做,避免横竖两套布局返工
5. **P2 设置窗口扩展(3 阶段 1)**——主题/背景/自定义文字/模块显隐顺序全部上 UI,替代手改 JSON
6. **P3 自由拖放(3 阶段 2)、待办(8)**——验证性功能,最后收尾
